### What the patch does
1. **Swaps the server.** Every `npx -y @modelcontextprotocol/server-github` becomes GitHub's official server, run the way its README recommends:
   ```yaml
   command: "docker"
   args: ["run", "-i", "--rm", "-e", "GITHUB_PERSONAL_ACCESS_TOKEN", "ghcr.io/github/github-mcp-server"]
   env:
     GITHUB_PERSONAL_ACCESS_TOKEN: "***"
   ```
   The token variable name is the same, so each example's `env:` block stays exactly as it was.
2. **Fixes the tool allowlists.** This is the part a blind find-and-replace would miss.
   - The archived server had `create_issue` and `update_issue`. The official server merges both into a single **`issue_write`** tool.
   - Hermes `tools.include` lists are exact tool names. Swapping only the package would leave allowlists naming tools that no longer exist, so users would silently lose issue creation.
   - Each `include:` list in a GitHub block now uses `issue_write`. `list_issues` and `search_code` keep their names.
3. **Keeps the tutorial's narrative intact** in `guides/use-mcp-with-hermes.md`.
   - The tutorial starts with a tight allowlist (Phase 1) and widens it when you "need issue updates too" (Phase 2).
   - Because `issue_write` grants both create and update, Phase 1 is now read-only (`list_issues`, `search_code`), and Phase 2 adds `issue_write`, with one sentence explaining why.
4. **Nix:** the Nix example uses `${pkgs.github-mcp-server}/bin/github-mcp-server` with `args = [ "stdio" ]`. I checked that nixpkgs packages the official server: `pkgs/by-name/gi/github-mcp-server`, built from `github/github-mcp-server` v1.14.0.
5. **Claude Code skill:** in `SKILL.md` and its generated page, the command becomes `claude mcp add -s user github -e GITHUB_PERSONAL_ACCESS_TOKEN=$GITHUB_PAT -- docker run -i --rm -e GITHUB_PERSONAL_ACCESS_TOKEN ghcr.io/github/github-mcp-server`. This is the form in GitHub's own README.
6. **Adds a note** under the stdio example in `user-guide/features/mcp.md`. It links the official server, mentions the binary and the remote endpoint (`https://api.githubcopilot.com/mcp/`), and says the old npm package is archived.

### How you could explain it in an interview
> "Hermes is an open agent framework, and its docs taught people to connect GitHub through an MCP server that had been archived, with npm literally saying 'no security guarantees'. That's a supply-chain problem hiding in copy-paste examples. The obvious fix is swapping the package name, but I checked what the replacement server actually exposes. GitHub's official server merged 'create issue' and 'update issue' into one `issue_write` tool. Hermes allowlists tools by exact name, so a naive swap would have made those allowlists silently drop the write tools. Users would think they'd granted 'create issue' and the agent just wouldn't have it. So I updated the allowlists too, and I re-ordered the tutorial so the first step is read-only and write access is an explicit second step, which is the least-privilege story the guide was already telling. I also checked whether there was a Nix package rather than assuming Docker, and I ran the project's own generator to prove the generated pages stayed in sync. For me it's a small example of treating tool permissions for agents as a contract you verify, not a string you replace."

## 4. Things I was unsure about
- **Docker vs. remote endpoint.** The issue offers three replacements: a local binary, Docker, or the remote endpoint.
  - I used Docker, because it keeps the `command`/`args`/`env` shape these stdio examples are teaching and it is GitHub's primary documented route.
  - It does add a Docker dependency where `npx` only needed Node. If a maintainer prefers the remote endpoint (`url:` plus an `Authorization` header), the change is mechanical. The note in `features/mcp.md` already points to it.
- **Typosquat risk.** The npm name `github-mcp-server` belongs to an **unrelated third-party package**, so nobody should "fix" these docs with `npx github-mcp-server`. Worth saying in review if anyone suggests it.
- **Generic `create_issue` examples left alone.** Some pages use `create_issue` in abstract filter-precedence examples that aren't tied to the GitHub server config (for example `mcp-config-reference.md` "Precedence", and the tool-search walkthrough). I left them to keep the PR scoped. A maintainer may want them aligned.
